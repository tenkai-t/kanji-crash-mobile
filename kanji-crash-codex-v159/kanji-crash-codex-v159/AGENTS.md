# Codex開発ルール — 漢字クラッシュ

このリポジトリは既存公開ゲームv159の引き継ぎです。新規ゲームとして初期化しないでください。最初に README.md、MIGRATION.md、GAME_SPEC.md、TEST_REPORT.md、PROVENANCE.json を読んでください。

## 絶対に守ること

1. 所持文字・instanceId・レベル・経験値・解放/装備ルビ・能力、文、段位、対人RP、戦績、枠、勲章、実績、ランキング、お気に入り、編成、設定を維持する。
2. 保存キー、プレイヤーID、ゲストtoken、復元コード、バックアップ形式、APIのownerキーを勝手に変更しない。移行エラーを「新規プレイヤー作成」で解決しない。
3. ユーザーがその変更を明示的に依頼していない限り、抽選確率、報酬、経験値、威力/重量、属性倍率、錬成条件、コスト、能力判定順を変えない。
4. 既存の一度限りの補填・記録リセット・ギフト受取を再実行しない。受取IDや履歴を付け替えない。
5. 演出・音・表示を抽選/獲得/消費から分離し、二重消費・二重付与を防ぐ。保存前の演出で結果を失わない。
6. 対戦・オート・練習・リプレイ・お気に入り・音付き動画保存を維持する。マイク録音や外部へのリプレイ送信を追加しない。
7. 現行フォントの字体とライセンスを維持する。WOFF2を別の書体で代用して「同じ」と報告しない。

## 作業の進め方

- ローカルの独立DBとテスト用の新規状態だけを使う。本番の復元コード/個人セーブをテストデータにしない。
- `dist/` はソースを含む。全削除不可。`server/generated/` と `dist/client/`・`dist/server/` はビルド生成物。
- 最小限の変更に限定し、ブラウザー/サーバーで共有するルールを両側で確認する。
- `npm ci` → `npm run verify:source`（初回の基準確認）→ `npm run build` → `npm run test:migration`。
- ゲーム変更後に verify:source が不一致になるのは変更の検出。比較基準を変更後の値で上書きしてテストを通すのではなく、変更したファイルと理由を報告する。
- 古い履歴依存テストはZIPにないコミットを参照する。未取得の履歴を創作しない。スナップショット不一致を理由に最新版を旧版へ戻さない。
- 実ブラウザー/実機で操作していない項目は「動作確認済み」と書かない。自動テスト、モック、コード確認を分けて報告する。
- `GAME_SPEC.md` の説明よりソースが優先。矛盾を見つけたら報告し、仕様変更として勝手に修正しない。

## 公開・外部操作

- ユーザーが明示的に承認するまで、本番公開、Sites/GitHubへのpush、DBのexport/import/migration、ドメイン切替、既存サイト削除、アクセス範囲の変更を行わない。
- この移行準備では公開・実データ移行は許可されていない。`.openai/hosting.json` の既存project_idを使って新規サイトを登録したり、既存サイトを上書きしない。
- ローカル起動用 `scripts/dev-local.mjs` と `tests/friend-server.mjs` は本番利用禁止。インメモリSQLiteであり、本番認証の代替ではない。
- `oai-authenticated-user-id` は元ホストで検証済みのヘッダーが付与される前提。別ホストでクライアント入力の同名ヘッダーを信用しない。
- 秘密鍵、APIキー、実ユーザーのtoken/復元コード、Cookie、個人セーブ、実DBをコミットしない。環境変数を必要とする変更では値をログに出さない。

## 完了時の報告

変更内容、維持した互換性、実行した検証、未確認項目、公開/データ移行を実施したかを明記する。ゲームバランスを変えた場合はユーザーの明示的な依頼と変更数値を示す。
