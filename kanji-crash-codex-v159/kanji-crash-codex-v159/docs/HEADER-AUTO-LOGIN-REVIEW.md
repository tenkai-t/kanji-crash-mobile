## 原因と変更

- ヘッダー: 共通glass-panelのbackdrop-filter: blur(14px)がヘッダー全体に適用されていた。文字自体へのblurやJSのscaleは見つからなかった。iOSの合成描画の影響を避けるため、このヘッダーだけ背景を同じ濃紺の不透明色とし、backdrop-filter（接頭辞付きも含む）を解除。文字サイズやフォントは維持。小幅・大きな文字ではタイトルとポイントを折り返し、高さを自動で確保する。実機のぼやけの原因と改善効果は未確定。
- オート: 対局準備のフッターに設定2項目と説明が常時展開されていた。既存input/ハンドラーを維持したdetailsへ変更し、summaryにOFF、ON、勝利後の自動継続を表示。対局開始条件、初期値、AI処理は変更しない。展開した設定項目は44px以上を確保。
- ログイン: POST後の例外をすべて保存競合扱いにし、GETでの再確認では競合を解消できなかった。またalreadyReceivedの場合は端末への報酬同期を行わなかった。ローカルAPIでサーバー確定後の応答消失、付与前503を再現し、二重付与せず復帰できる処理を追加した。
- 通信結果不明の場合、受取状況と認証済みguest/stateを取得。端末との差がちょうど1回の正式報酬（文、かけら、ordinal）のみで、ほかの保存項目と一致する場合だけサーバー保存を反映する。再読み込み後も同じ条件で回復できる。無関係な進行差、更新中の端末状態、保存保護は上書きしない。
- 付与されていないことをsnapshot/revisionで確認できた場合だけ、今回の通信で設定した競合を解除して再試行可能にする。再確認も失敗した場合は未確認表示と再確認ボタンを残す。ログイン関連のリクエストは15秒で中断し、成功扱いにしない。
- 状況取得の失敗理由を画面へ表示する。表示はtextContentで行い、資格情報をログへ出さない。

## サーバー・DB確認

server/worker.mjsのGET/POSTは既存ゲスト認証とownerキーを照合する。server/login-bonus.mjsはサーバーJST日付とplayer/day・player/ordinalの一意制約、D1 batch、guest revisionで付与を制御する。guest state保存ではordinalを照合して古い状態の上書きを拒否する。
login_bonus_claimsは既存schema処理がCREATE TABLE IF NOT EXISTSで準備する構成。今回スキーマ/サーバー/マイグレーションは変更していない。Cloudflare生成設定のDB/ASSETSとDB IDをコード上確認したが、実際の本番バインディング・テーブル・行・障害ログは未確認。実環境からサイトへのHTTPはCONNECTトンネル403で取得不可。本番での受取不能の原因が今回再現した通信経路と同じかは未確定。
