# ログイン自動表示・BGM切替の修正（2026-10-25）

作業ブランチ: `fix/login-popup-bgm-switch`。ローカルで実装と検証を完了後、ユーザーから公開依頼を受領。新サイトの公開反映用ブランチは`cloudflare-test`。本番DBの直接操作や旧Sitesへの操作は行わない。

## 原因と変更

### ログインボーナス

従来はdetailsを開いたときだけ受取状況を取得し、起動時の表示処理はなかった。

- サーバーが返す日付・受取状況を確認後、未受取の日に自動表示する。
- 初回チュートリアル、復元確認等のdialog、対局、マッチング、召喚、錬成、動画保存、バックアップ処理の間は待機する。非表示タブでは開かない。
- サーバー応答にserverNowを追加。次の更新までの時間はnextResetAt-serverNowで計算し、端末の時計で日付を決めない。
- 非表示から戻ったとき・再接続時にも再確認する。通信失敗は未確認として扱い、再確認ボタンを出す。
- 日付とプレイヤーIDを組にした新しい端末用の表示履歴だけを追加。表示済みでも受取判定は常にサーバーに従い、記録画面から再度開ける。
- 自動表示によるPOSTはしない。「今日の報酬を受け取る」で従来の保存・二重付与防止処理を使う。
- 濃紺・和紙の模様・金色の見出しで統一。今回、受取済み、これからを文字と枠で区別する。
- 報酬一覧だけをスクロールさせ、受取・再確認ボタンは画面内に保つ。
- キーボード操作、Escape、フォーカスの復帰、受取中の閉じる操作の抑止を用意。

報酬量とサイクル、保存キー、ゲストID、復元コード、ギフト履歴を変更しない。
報酬の同時受取と古い保存の防止は既存のサーバー処理を維持する。

### BGM

3つのWAVのSHA-256は異なる。実ブラウザーでも、デコードした波形が異なる3つのAudioBufferが再生開始されることを確認した。
一方で、旧コードをローカルで再現すると、2曲目をHTTP 503にした場合、選択値は2曲目なのに前の曲の音源1個が残り続けた。旧画面はその読込失敗を表示せず、再試行ボタンもなかった。
正常通信時には元から切り替え可能であり、ユーザー実機で発生した原因が通信失敗だったとは断定しない。3曲は同じ系統の音色と和声進行を共有し、曲の違いは控えめ。今回は音源を作り直していない。

変更内容:

- 選択中と再生中の曲名を分けて持ち、実際の再生開始後に再生中として表示。
- 読込中・失敗を音設定に表示。12秒で読込/デコード待ちを打ち切り、可能ならfetchをabortする。
- 切替失敗時は前の曲も停止し、前の曲を選択曲と誤認させない。
- エラーを曲ごとに管理し、遅れて完了した別曲の失敗が現在の曲の表示を上書きしない。
- 再試行操作で待ち時間の制限を解除し、すぐ再読込できる。
- 正常時は0.35秒のクロスフェードで切替。素早い連続選択でも最後の選択だけを再生する。
- オフ時の選曲はオフを維持。既存の効果音・BGM音量、選択保存、Safariの復帰、動画保存への曲指定は維持。

### 選択欄の色

従来はselect/optionの色指定がなく、周囲から白い文字を継承する一方、ネイティブ選択肢の背景が明るい環境では読みにくくなり得た。
選択欄とoptionを和紙色の背景＋濃紺の文字にし、select自体にcolor-scheme:lightを指定。フォーカス枠と無効状態も明示。音設定のTab移動にselectを含めた。
Chromiumの計算上の文字/背景コントラストは欄・optionとも7:1以上。
iOSの選択肢一覧はOSのネイティブ描画でCSSが完全適用されないため、実機の見た目は未確認。
