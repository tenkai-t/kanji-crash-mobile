# 練習画面の閉じる操作・リプレイ動画保存：公開前の報告

2026年10月18日。既存の漢字クラッシュを対象に実装。現時点では本番に公開していません。

## 変更内容

### 遊び方を練習：右上の×

既存CSSには、100dvhから16pxだけを引く強制的な高さ指定、安全領域を考慮した別の高さ指定、小さめのヘッダー指定が併存していました。ホーム画面からの単独起動では上端の安全領域が足りなくなる可能性があります。実機で不具合そのものを再現できていないため、これを確定した原因とはしていません。

今回追加した対策：

- ノッチ・ステータスバー・ホームインジケーターを考慮し、上下左右の安全領域に8pxの余白を加える。
- visualViewportの高さ・幅・位置に追従し、起動・回転・拡大等で見える領域が変わった際に寸法を更新する。
- ヘッダーを練習内容のスクロール領域から分離する。
- 右上の×を48×48 CSS pxのタップ領域にし、縮まないように固定する。
- 短い画面や大きな文字で内容が収まらない場合、内容部分をスクロールできるようにする。下部の操作も独立した領域とする。
- 練習盤面の縦横比を1:1に維持する。

閉じる際は既存の closeGameTutorial() をそのまま呼びます。練習のルール、配置、説明内容、閉じた先の処理は変更していません。

### リプレイ：動画を保存

既存リプレイの画面に「動画を保存」を追加しました。

1. 「記録」→「リプレイ」などから、既存の方法で対局を開く。
2. 必要に応じて画質を選ぶ（端末に合わせる／軽量／標準）。
3. 「動画を保存」を押す。
4. 画面を開いたまま、リプレイの長さ＋約3秒待つ。
5. 完成後、プレビューを確認し、「共有して保存」または「ファイルをダウンロード」を選ぶ。

画質は軽量540×960・20fps、標準720×1280・24fps。いずれも縦横比9:16で、盤面は正方形の領域に描画します。端末に合わせる場合は、ブラウザが提供するメモリ・CPU情報を参考に選び、不明なら標準にします。実際の録画フレームレートは端末・ブラウザに依存します。

録画するのは専用キャンバスのみです。ゲーム名、対局名、双方の名前、盤面、コマ・回転、既存リプレイの能力表示、最後の結果を含めます。保存用のボタン、進捗、メニューは含めません。最初の約0.8秒と最後の約2.2秒を静止表示します。

既存の盤面描画を drawReplayBoard() として共通化し、通常再生と動画の両方から使用します。録画はリプレイのコピーを読み取り、ゲームの物理演算を再実行しません。音声は付けていません。

## 形式・端末ごとの保存方法

MediaRecorderとCanvasのcaptureStreamを使用します。外部サービスへのリプレイ送信、サーバー側の変換、有料サービスは追加していません。カメラ・マイク・画面全体の録画許可も要求しません。

MP4を優先し、APIの対応判定とRecorderの生成結果に応じてWebMを選びます。生成後は先頭のコンテナ識別子も確認し、実際の形式と一致する拡張子で保存します。WebMをMP4に見せかけたり、変換したと表示したりしません。コンテナ確認だけで映像の正常なデコードまで保証できるわけではありません。

| 環境 | 利用する方法 | 制限・確認状況 |
|---|---|---|
| iPhone Safari・ホーム画面起動 | MP4等の生成とファイル共有が使える場合、共有メニューから保存先を選ぶ | 「ビデオを保存」「ファイルに保存」などの表示はOS・形式に依存。実機未確認。写真へ直接自動保存する機能ではない。 |
| Android Chrome・ホーム画面起動 | 生成可能なMP4またはWebMを共有・ダウンロードする | 保存先アプリや再生対応は端末に依存。実機未確認。 |
| ファイル共有に非対応 | ダウンロードリンクを使う | ブラウザによってはファイルのプレビューが開く。そこから保存する。 |
| WebMだけを生成できる環境 | WebMとして保存する | 写真アプリで扱えない場合はファイル管理・対応再生アプリを使用。 |
| 録画API自体が非対応 | 理由と代替方法を表示する | 対応するSafari／Chrome等で開くか、端末側の画面収録でリプレイを録画する。アプリが画面収録権限を要求するわけではない。 |

動画作成の処理本体は「動画を保存」を使う際に読み込みます。全プレイヤーの起動時に大きな動画ライブラリを読み込む方式にはしていません。

## 中止・失敗・後片付け

- 二重作成を防止し、作成中は再生・シーク等を一時停止する。完了・中止後は元の操作が使える。
- 作成中は中止できる。別ページへの移動、リプレイを閉じる操作、画面の非表示でも録画を中止する。
- タイマー、アニメーション要求、録画トラック、Recorderのイベントを解除し、描画用バッファを解放する。
- 完成した動画は、共有メニューを取り消しても保持する。画面を閉じずに再び保存できる。
- 作り直す場合とリプレイを閉じる場合は、古いBlob URLと動画プレビューを解放する。
- 録画データの増え過ぎ、途中停止、描画停止、空データ、不明な形式、Recorderのエラーを検出した場合は作成を中止する。リプレイ自体や所持データは削除しない。
- 端末容量の残量やOSによるプロセス強制終了を完全に検出・防止できるわけではない。完成した動画は端末への保存操作が必要で、閉じた後までゲーム内に動画ファイルを保管しない。

## 未確認のこと

この実行環境では対応する自動操作ブラウザとスマホ実機を使用できないため、以下は確認済みとはしていません。

- ホーム画面起動・Safari・Androidでの見た目、実際のタップのしやすさ。
- 大きな文字、回転、全練習ページ、スクロール前後での実レイアウト・操作。
- ブラウザのMediaRecorderによる実動画の生成、映像のデコード・再生、画質・フレーム落ち・ファイル容量。
- iPhoneの写真／ファイル、Androidの保存先への実保存と共有先の表示。
- 実機でのメモリ・容量不足、OS強制終了、長いリプレイを繰り返し録画した場合の挙動。

公開後はまず実機でこの2機能を確認し、問題があれば直前のv154へ戻せる構成です。保存形式やサーバー処理は変えていないため、今回の変更を戻すためにプレイヤーデータを巻き戻す必要はありません。
